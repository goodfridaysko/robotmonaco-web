# robotmonaco.com

Static site for **ROBOTMONACO**: humanoid robot hire with an operator for events, brand activations and
marketing in Monaco and the French Riviera, plus custom robot software and AI assistant builds.

English lives at the root, French mirrors every path under `/fr/`.

## Build

```bash
python3.12 build.py            # content/ + src/ + photos/ -> dist/
python3.12 build.py --serve    # build, then serve on http://localhost:4175 with clean URLs
```

Python 3.12 or newer, no dependencies. `tools/make_images.py` additionally needs Pillow.

## Layout

| Path | What it holds |
|---|---|
| `build.py` | the whole generator: every page goes through `page()`, so meta, schema, breadcrumbs, hreflang and the sitemap cannot drift apart |
| `content/config.json` | domain, contact, prices, the fleet and the page order. No prose, so it is never translated |
| `content/en/`, `content/fr/` | all copy, one file per page type. Both trees have the same shape |
| `content/BRIEF.md` | the editorial brief the copy was written to: voice, hard facts, allowed icons and photos |
| `src/` | styles, viewer script, icons, fonts, logos and `models/montari.glb`, copied to `/assets/` |
| `photos/` | every visual, generated by `tools/make_images.py` from the robot renders |
| `static/` | files served from the web root: favicons, `send.php`, and `htaccess.base` |
| `tools/` | `make_images.py`, `brand_glb.py`, `deploy.py` |

## The 3D robot

The homepage hero is the real model, turnable in the browser. `src/models/montari.glb` **is committed**:
a build machine without it would silently fall back to a flat photo, which is exactly the regression the
sibling site hit once.

`tools/brand_glb.py` swaps the wordmark printed on the robot's chest, which the model carries as its own
`decal` material:

```bash
python3.12 tools/brand_glb.py src/models/montari.glb src/img/logo-chest.png
```

## Deploy

Pushing to `main` builds the site and mirrors `dist/` to the web root over FTPS
(`.github/workflows/deploy.yml` → `tools/deploy.py`). It needs `FTP_HOST`, `FTP_USER` and `FTP_PASS` as
secrets of the GitHub environment **production**.

The uploader only adds and overwrites, it never deletes. Sitemaps and `robots.txt` go up under a temporary
name and are renamed into place, so a crawler never reads a half-written file.

## Adding a page

1. Add the copy to `content/en/<file>.json` and the same keys to `content/fr/<file>.json`.
2. List its slug in `content/config.json` if it belongs to a set (`useCaseOrder`, `serviceOrder`).
3. Rebuild. The sitemap, the hreflang pairs and the footer pick it up on their own.
